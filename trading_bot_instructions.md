# Trading Bot Instructions

Single source of truth for this paper-trading bot. Every build prompt reads this file first.
(Interview defaults were used where answers weren't available — see "Open items" at the bottom. Edit freely; the bot follows this file.)

## 1. Project Goal
A paper-trading bot for **BTCUSDT on the 5m timeframe** that executes a simple moving-average crossover strategy with razor-sharp consistency, logs every decision, and gets smarter over time by reading its own trade memory before acting. Paper/test mode comes first because strategies must prove themselves on fake money before a single dollar of real capital is exposed — the majority of losses happen while the system (and its owner) is still learning.

## 2. Safety Rules
- Paper trading only. **No live-trading code path exists in this project** and none may be added by any prompt.
- No API keys pasted into chat or committed to source. Future broker credentials live in the MCP client config or a secrets store; prefer restricted / sub-account / paper keys.
- No secrets in frontend code (no frontend exists).
- No order without a passed risk check, and every decision must print a plain-English reason.
- Real market data only — if data is unavailable, the bot stops and says so; it never invents candles or fakes results.

## 3. Strategy Rules
- Indicators: **9-period and 21-period simple moving averages** of closes, computed on **closed candles only** (the still-forming candle is dropped, so signals never repaint).
- Entry: **BUY** when the fast MA crosses above the slow MA on the latest closed candle.
- Exit / short signal: **SELL** when the fast MA crosses back below the slow MA.
- No fresh crossover → **HOLD**, with the reason stated.
- Replay/scan scoring model: enter at signal-candle close, exit at close 12 candles later (~1 hour), round-trip fee + slippage = `FEE_BPS` from `.env` (code default 10; deep research puts real BTC round-trip costs near 28 bps, so 25–30 is the honest setting — every replay/scoring line prints whichever value was active).

## 4. Risk Rules
- Position size: **0.001 BTC** per paper order (`QUANTITY`).
- Max position: **0.003 BTC** (`MAX_POSITION`). Any order that would exceed it → final action **SKIP**, reason logged.
- Costs: `FEE_BPS` round-trip in all replay and scan scoring — set in `.env`, code default 10. Deep research estimated ~28 bps real round-trip cost for BTC; results computed at 10 bps overstate the edge.
- Stop loss / take profit / max daily loss: **not yet defined** — to be added after a backtest justifies specific levels. Until then the fixed replay horizon is the only exit model, and the bot stays on paper.
- Stock symbols (paper): sized in shares (`STOCK_QUANTITY`/`STOCK_MAX_POSITION`), scanned regular hours only. **PDT reality for any future live plan: a margin account under $25k gets 3 day-trades per 5 sessions — a 5m stop-and-reverse strategy is not livable under PDT at small size.** Crypto has no PDT.

## 6. Memory Rules
- `data/ledger.csv` logs every paper/replay trade and every skipped decision. Header: `timestamp,symbol,action,price,quantity,reason,mode,outcome,pnl`.
- `data/learnings.md` stores plain-English lessons distilled from **real** closed outcomes only — never seeded, never invented.
- Before any BUY or SELL the bot reads both files and asks: (1) has this symbol lost on a similar setup before? (2) does the learnings file warn about this setup? (3) is this signal repeating a known bad trade?
- A setup is blocked (SKIP) only when the ledger shows **≥ 2 real prior losses with net-negative PnL** for that symbol + setup tag AND learnings.md warns about it (`MEMORY_MIN_LOSSES`).
- If memory is empty, memory mode says to run `replay:raw` first — it never skips without a real recorded reason.
- `data/trials.csv` (append-only; `memory:reset` never touches it) discloses **every configuration ever backtested** with its metrics — the assessability requirement from the deep research (F6). Every replay run logs itself automatically; externally-run tests (e.g. TradingView) get recorded rows with their source labeled.
- Live scan trades are logged `open`, then scored after the 12-candle horizon (`npm run score`, auto-run at the start of every scan): the signal candle is located in real fetched data and verified against the recorded entry price before any outcome is written — if it can't be verified, the row stays open and the reason is printed. Scored losses refresh `learnings.md`, so memory learns from forward decisions, not just replays.

## 7. Definition of Done
- Commands that work: `npm run scan`, `npm run score`, `npm run positions`, `npm run replay:raw`, `npm run replay:memory`, `npm run memory:reset`.
- Forward data accumulates unattended: launchd agent `com.jalenedusei.trading.scan` runs `npm run scan` every 5 minutes over the `SYMBOLS` universe in `.env` (currently BTCUSDT, ETHUSDT, SOLUSDT, SPY, QQQ — chosen by liquidity; edit freely), appending to `data/scan.log` (status: `launchctl print gui/$(id -u)/com.jalenedusei.trading.scan`; stop: `launchctl bootout gui/$(id -u)/com.jalenedusei.trading.scan`). Note: launchd pauses while the Mac sleeps — forward data has honest gaps unless the machine stays awake.
- Declined entries (regime filter or memory block) are logged as mode `scan-filtered` counterfactuals and scored like real trades, so filters themselves are measurable against forward data.
- Second agent `com.jalenedusei.trading.tsmom-daily` (hourly) runs the watch-status TSMOM-28 book with **real paper execution**: long-only ETH/BNB/ADA/LINK + SPY/QQQ/AAPL/NVDA (stocks defer orders/exits to market open; Alpaca daily bars close on 04:00 UTC boundaries), both-sides SOL simulation-only. FEE_BPS=30, 28-candle horizon (counted in closed trading candles — exact for stocks and crypto), log `data/tsmom-scan.log`. Each scan config scores only rows whose setup-tag interval matches its own, and every signal candle is acted on at most once.
- Third agent `com.jalenedusei.trading.tsmom-monitor` (1st of each month) recomputes the Trial 07 portfolio construction into `data/monitor_tsmom.csv` with the pre-registered regime alarm (trailing-12-month excess < 0). First reading 2026-07-15: trailing-12 +1.30%/mo (ok), trailing-6 −0.36%/mo (warning). Full paper-phase operating rules + promotion gates: `docs/paper_phase_protocol.md`.
- `scan` prints timestamped lines for market, signal, risk, memory, and the final decision.
- `replay:raw` prints a trade-by-trade table plus summary metrics (setups, wins, losses, win rate, avg PnL, best/worst, max drawdown).
- `replay:memory` prints the raw-vs-memory comparison and logs its decisions to the ledger.
- Confirmed: **no real order is ever placed** — there is no live endpoint anywhere in the codebase.
